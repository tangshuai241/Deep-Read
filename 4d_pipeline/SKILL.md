# 四维多 Agent 书籍拆解

> **前置检查**：执行任何操作前，先确认仓库根目录 `config.yaml` 存在且 `llm.api_key` 不为空。
> 如果不存在或未填写，引导用户运行 `python install.py` 并填写 DeepSeek API Key。
> 获取地址：https://platform.deepseek.com

## 核心原则

1. **上下文隔离**：四个拆解 Agent 彼此不可见，避免污染
2. **预处理禁止分析**：预处理 Agent 只做分段/索引/分类，不产出任何分析性判断
3. **汇总不抹平矛盾**：矛盾是信号，标注"需人工裁决"，不自行仲裁

## 工作流总览

```
输入：全书文本
  │
  ├─→ [Agent 0·预处理] → 章节分段 + 术语索引 + 书型分类
  │
  ├─→ [Agent A·骨架] ──┐
  ├─→ [Agent B·思想] ──┼── 四维并行拆解（独立上下文）
  ├─→ [Agent C·论证] ──┤
  ├─→ [Agent D·叙事] ──┘
  │
  └─→ [Agent 5·汇总] → 覆盖率 + 一致性 + 冗余度 + 矛盾标注 + 可信度
```

总耗时：依文本规模和复杂度而异：
- 短书/叙事（10-12章，~150K chars）：约 15-20 分钟
- 中篇非虚构（30-40 章，~330K chars）：约 20-25 分钟
- 宗教经典（4 品但有密集注释层，~140K chars）：约 25-30 分钟
- 瓶颈在 Agent 5 汇总验证（交叉验证复杂时可达 5+ 分钟）

## 阶段零：书籍预处理（Agent 0）

**输入：** 全书文本（txt/markdown/epub 提取）

**步骤：**

1. **章节分段**
   - 识别章节边界（目录/标题模式匹配）
   - 输出：[章序号, 章标题, 起始段, 终止段, 字数]

2. **关键术语索引**
   - 提取明确定义的术语（"所谓X是指...""X定义为...""X即..."模式）
   - 提取高频专有名词（出现≥5次，非停用词）
   - 输出：术语清单，每项标出现位置和频次

3. **书型分类**
   - 判断维度：论证型/叙事型/混合型/参考型
   - 输出：书型标签 + 置信度

**产物：** `预处理产物.json`
**禁止项：** 不得输出"本书核心思想""作者主要观点"等分析性内容

## 阶段一：四维并行拆解

四个 Agent 用 `delegate_task` 并行启动，每个收到相同的预处理产物和全书文本，但彼此不可见。

---

### Agent A — 骨架拆解

**指令核心：** "只用 MECE 和金字塔原理做结构分析，禁止使用心理学/哲学/叙事学术语"

**步骤：**

1. MECE 全书结构——将全书主题归入互斥且穷尽的维度（如：理论框架/方法论/案例/工具/批判）
2. MECE 章内结构——每章提取核心主题+子主题
3. 金字塔归约——章结论→篇结论→全书核心结论
4. 结构完整性自检——覆盖矩阵

**产物：** `骨架拆解产物.json`（维度清单、MECE树、金字塔、覆盖矩阵）

---

### Agent B — 思想拆解

**指令核心：** "只用第一性原理和概念本体做思想分析，禁止使用'第X章''作者认为'等结构表述"

**步骤：**

1. 底层假设提取——逐章追问"作者默认了什么没说的前提"
2. 核心概念提取——识别作者原创或重点使用的概念
3. 概念本体建模——定义 is-a / part-of / causes / depends-on / contradicts 关系
4. DIKW 层级标注——每个概念标 D(数据/事实) I(信息) K(规律) W(智慧)

**产物：** `思想拆解产物.json`（假设清单、概念卡片、概念关系图、DIKW分布）

---

### Agent C — 论证拆解

**指令核心：** "只用论证映射和 Bloom 认知层级做逻辑分析，禁止讨论概念含义/叙事技巧"

**步骤：**

1. 论证链路提取——[前提]→[推理类型:演绎/归纳/类比/反证]→[结论]
2. 论证质量评估——逻辑谬误检测、证据充分性、前提可验证性
3. Bloom 认知层级分布——每章标记忆/理解/应用/分析/评价/创造
4. 关键论证链——识别支撑全书核心结论的承重墙论证

**产物：** `论证拆解产物.json`（论证链路表、质量打分、Bloom分布、关键链）

---

### Agent D — 叙事修辞拆解

**指令核心：** "只用框架分析和修辞三角做表达分析，禁止讨论概念定义/论证有效性"

**步骤：**

1. 框架分析——识别核心隐喻和认知框架（如"市场是战争""大脑是计算机"），统计频次
2. 叙事语法——识别叙事弧（平衡→打破→冲突→转折→新平衡）
3. 修辞三角——每章 Ethos(权威)/Pathos(情感)/Logos(逻辑) 比例
4. 框架一致性检查——同一框架跨章使用是否稳定，有无冲突

**产物：** `叙事修辞拆解产物.json`（框架清单、叙事弧、EPL分布、框架冲突）

---

## 阶段二：汇总验证（Agent 5）

**指令核心：** "不修改四个维度原始产物，只做对比/打分/标注。矛盾标注'需人工裁决'不自行仲裁。"

**步骤与量化指标：**

```
1. 覆盖率检测
   指标：覆盖率 = 被≥1维覆盖的术语 / 总术语数，目标 ≥ 90%
   多维覆盖=强信号，单维覆盖=弱信号，零覆盖=盲区

2. 交叉一致性验证
   指标：一致性 = 1 - (矛盾数 / 对比总数)，目标 ≥ 0.85
   一致=🟢，角度不同但不矛盾=🟡，明确矛盾=🔴

3. 冗余度检测
   指标：冗余率 = (总节点 - 去重后节点) / 总节点，目标 ≤ 20%

4. 交叉验证增强——被≥2维独立验证的发现，置信度提升一级

5. 矛盾标注——不抹平，列出需人工裁决的冲突点
```

**产物：** `汇总验证产物.json`（覆盖率得分、一致性得分、冗余率、矛盾清单、综合可信度 0-100）

## 工程执行方式

用 `delegate_task` 分批并行：

```python
# 阶段零：串行预处理
delegate_task(goal="预处理全书文本...", context=book_text)

# 阶段一：四维并行
delegate_task(tasks=[
    {"goal": "骨架拆解...", "context": preprocess_output},
    {"goal": "思想拆解...", "context": preprocess_output},
    {"goal": "论证拆解...", "context": preprocess_output},
    {"goal": "叙事拆解...", "context": preprocess_output},
])

# 阶段二：汇总收口
delegate_task(goal="汇总验证四维产物...", context=all_four_outputs)
```

## 文本类型适配

### 非虚构/学术著作（如《思考，快与慢》）

- Agent B 的第一原理可能超过 10 条（思考快与慢产出 12 条，42 个核心概念，57 个本体三元组）
- Agent C 的论证链路密集：61 个论证单元，20 个经典实验需标注为"实证锚点"
- Agent D 的 EPL 分析：非虚构中 Ethos 占主导（学术权威），Pathos 通过思想实验发挥作用
- 总耗时参考：333K 字符约 24 分钟

### 宗教/东方哲学经典（如《坛经》）

- Agent C 的论证类型必须跳出西方逻辑框架：使用"问答/引用/偈颂/譬喻/学术"五类替代"演绎/归纳/类比"
- Agent C 的认知层级用"信/解/行/证"替代 Bloom 分类
- Agent D 必须区分文本地层（口述→编纂→注释），各层修辞应独立统计
- MECE 骨架 vs 互摄思想：Agent A 的互斥分类与 Agent B 的概念互摄会产生产物级矛盾，在汇总阶段标注为"方法论张力 → 需人工裁决"，不计入一致性扣分
- 可信度参考：坛经 79/100（偏低源于方法论张力而非拆解质量差）

### 叙事文学（如《悉达多》）

- Agent C 的论证链路稀疏（34 条），以人物行为因果链为核心
- Agent D 是主力维度：核心隐喻（河）、叙事弧（双重觉醒结构）、EPL 全图
- 可信度参考：87/100

- 叙事/文学类书籍的主观性天然高于论证型，一致性指标可放宽到 0.75
- 零覆盖不等于拆解失败——可能是术语为过渡性内容，不足以成为概念
- 可信度评分是相对指标，不跨书比较
- **非西方文本（佛教经典、东方哲学）**：MECE 框架与佛教缘起性空/圆融互摄逻辑存在结构性张力。Agent A 强制互斥分类会与 Agent B 的概念互摄关系产生矛盾——这不是拆解错误，是方法论本身的边界。标注为"需人工裁决"，不强制拆解也不掩盖矛盾
- **多层文本（口述→编辑→注释）**：Agent D 需区分文本层（如唐口语/宋编辑/现代注释），各层修辞策略不同，不应混合统计

## 输出产物目录

拆解产物统一写入 `{BOOKS_DIR}/{书籍识别名}/analysis/`，其中 `{BOOKS_DIR}` 从 `config.yaml → paths.books_dir` 读取：

```
{BOOKS_DIR}/
├─ siddhartha/analysis/          ← 7 个 JSON + full_text.txt
├─ thinking_fast_slow_中信/analysis/
├─ 坛经_中华书局/analysis/
```

书籍识别名从 EPUB 文件名去 .epub 得到，用下划线连字符替代空格/特殊字符。

> **配置**：`config.yaml → paths.books_dir`（默认 `~/TaskOS/books`）。无配置时可用环境变量 `BOOK_TOOLCHAIN_BOOKS_DIR`。
